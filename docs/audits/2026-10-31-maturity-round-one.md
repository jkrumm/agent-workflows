## 1. Telemetry and usage tracking

Coverage by layer, from the code and the DB:

- Run span `agw.run <workflow>` and step span `agw.step <id>` are emitted by the middleware for every run, with tokens (5 kinds), cost, `unpriced_calls`, tool calls, friction counters and error kind. 4243 of 4248 runs have a `trace_id`; the 5 without are review (4) and eval.run (1), probably runs refused before the run hook. Tool spans exist only as OpenCode's own spans. No model-call spans.
- Journal: every agent step carries model, tokens, cost, `usage_by_model` (3446 of 3467 agent steps priced; 3 `unpriced_calls` on Haiku-eu, 2 on DeepSeek). Code steps hold usage only when a capability reports it (`addUsage`), including free web calls (`direct`, `hyperdx`, `npm`) as 0-cost rows.
- Usage outbox (step rows -> `usage.records`): 7962 of 10482 steps synced, 0 errors, nothing stale beyond an hour. It filters steps with tokens or cost, so web/free steps never reach usage (by design).
- Workflows that run end to end but record no cost: `check` (agent step skipped when checks pass; 30 of 34 runs NULL), `prose-gate` (35/35, a deterministic gate), `learnings.*`, `audio.ping`, `eval.run`/`eval.compare` (NULL although children spend), `door.speech` (31 NULL, TTS call failed with 400), `review.ocr`/`ocr` (blocked by the wallet gate, and unpriced even when it runs).
- Per-model weekly spend (agent steps, last 7 days): terra $65.5 (729), haiku-5-5 $21.6 + haiku-eu $13.9, deepseek-flash $14.1, sonnet-5-5-eu $17.1 + sonnet-5-5 $3.4. Haiku and Sonnet are the eval arms of 2026-10-28/30 and the live routes.json override described above; Haiku at max effort costs about $0.28 per angle.
- Spend by purpose (root runs): prod $103.75, eval $72.18, verify $0.29, build $0.77.

## 2. Evals

Cases (`eval/<wf>/cases.jsonl`): review 138, research 28, brain 10, prose 10, speech 10, transcriptions 10, image 8, otel 8, check 7, diagram 6. Scorers: brain, check, diagram, image, otel, prose, research, review (767 lines total). No cases for narrative, overview, prose-polish, image-icon (covered only by a byte-identical golden test), retrospective, learnings, podcast, smoke, nor any capability.

Persistence: zero eval results in git. `reports/<ts>/{report.md,report.json,results.jsonl}` exist for 7 runs on 2026-10-28 (review/check vs the retired gateway) outside the repo; `eval.run` outputs and `scores` live in Postgres. Nothing links a route/prompt change to a result, and `README` forbids committing case data (correct: cases hold private code). The harness already splits an "aggregate (safe to publish)" section from the per-case section.

A committed report (one per tier change, e.g. `docs/evals/<yyyy-mm-dd>-<tier>.md`) should contain only the publishable aggregate:
- what changed: tier, old and new route (model, effort, wire), route-table sha, workflow versions and fingerprints, OpenCode version
- case set: workflow, case count, hash of `cases.jsonl` (not content), scorer version, seed, concurrency, judge on/off
- per metric: value, 95% bootstrap CI, threshold, pass, for both arms (paired old tier vs new tier, not vs gateway)
- cost and wall: total, median per case, tokens, `unpriced_calls`, error/refusal rate
- verdict (`better|not-worse|worse`), warnings (mixed scorer versions, n<10), and the `eval.run` run ids so the numbers can be re-read from `agw.runs`
Per-case rows stay private. Add a small `agw eval report --commit` that renders this and refuses a report with `unpriced_calls>0` or n<10.

## 3. Tests

Totals by package (test blocks): host 1154, audio 694, capabilities 507, opencode-host 138, middleware 103, runtime 97, routes 87, cli 71, eval 69, limits 25, testing 3. `make check` needs Postgres; each file gets a throwaway schema, so most host/runtime/middleware tests are integration against real Postgres, with unit tests for pure modules.

Provider isolation: `ChatPort`/`DecisionPort` in `capabilities/src/transports/port.ts` with `fake-transports.ts` and a fake HTTP server (`fake-iu-server.ts`); web, image and audio each have their own fakes; the OpenCode host runs against a fake binary. Real endpoints only behind `AGW_LIVE=1` (`capabilities/live.test.ts`, `hdx.live.test.ts`, three `opencode-host/test/live*.test.ts`), none in CI. So tests do not hit real providers by default; live proof is `make verify` and per-wave verifiers.

Gaps: the cross-package fakes are not in `packages/testing`; the usage sink test skips outside the mini; no test asserts that the deployed route table (including `routes.json`) resolves and prices; `limits` has 25 tests for the wallet/runaway logic that is already killing legitimate runs.

## 4. Drift and debt

See the table. Most urgent are the Haiku override on the mini and the direct Anthropic key bypassing the IU wallet/key accounting (an AGENTS.md contradiction). `IU_ANTHROPIC_BASE` is dead. The `iu-anthropic` wire is reachable only through ocr.ts, `model-call.ts`, podcast llm and tests, with no live route; it is the natural seam for the planned direct single-call wire, so either extend it (base `api.anthropic.com`, structured outputs) or delete it now to avoid two Anthropic implementations.

Interactions with the known upcoming work:
- Tier collapse (FAST/EASY/HARD/DECIDE): the seats in `_shared.ts` become tiers; first delete the effort/maxOutputTokens overrides above and move fallback policy into the tier so a tier edit is one edit. `routes.json` must be removed or committed first, else tiers will be silently overridden per route as now. Step rows need the tier name (add `route`/`tier` column) to make the committed per-tier reports queryable.
- Direct Anthropic single-call wire: needs the wallet/`iu_key` accounting decision (direct key is outside the IU cap), `longPrompt` multiplier handling already present in `TERRA_RATE`/Haiku overrides, and the model-id normalisation above, since Anthropic echoes dated ids. `z.toJSONSchema` output needs a strict-mode check per workflow schema (optional vs nullable) and a test per capability schema.
- Committed eval reports: eval cost roll-up (parent linkage) and eval cases for the uncovered workflows must come first, otherwise a tier change cannot be judged for the narrative/podcast/overview/retrospective paths.

## 5. Design improvements (evidence-backed)

1. Record the route id and tier on every journal step and use the route's model id, not the provider echo (31 distinct model strings today).
2. Make eval replays children of `eval.run` and roll cost up; gate with the wallet.
3. Take production route overrides into git; fail `make verify` when `AGW_ROUTES` contains an id/model not in a committed file.
4. Distinguish `cost = 0`, `cost NULL (unknown)` and not-applicable; set `unpriced_calls` on unknown-cost failures (door.speech 400).
5. Mark door errors as failed runs (or add `outcome` column) so door failure rates are a run-status query.
6. Journal partial spend of failed agent steps from the OpenCode message API, and look at the "Compaction summary reached the output token limit" failure (6 of the 16 failed review steps this week; a route/maxOutputTokens setting problem on the opencode wire).
7. Review the runaway cap: p95 x10 wall of 31 min already trips on legitimate deep reviews (4 failures; two others on cost $1.65 vs $1.53).
8. Consolidate fakes into `packages/testing`; move `check`-style "skipped agent step" into a distinct `skipped` status so null cost is not ambiguous.
9. Delete `IU_ANTHROPIC_BASE` and the Haiku-era comments; update AGENTS.md status and the "IU tokens only" statement.
