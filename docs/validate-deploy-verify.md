# Validate, deploy and verify

The summary is in the root `AGENTS.md`. This is the full command table, moved verbatim from it.

Bun workspaces (`packages/*`), pinned toolchain per `package.json` devDependencies (the S3 spike, `docs/spikes/s3-stack/REPORT.md`, chose the stack; its lint and format row is superseded). `docs/spikes/**` is
excluded from every tool.

| Command | Runs |
|-|-|
| `make check` | `bun install --frozen-lockfile` first (stale `node_modules` never passes), then `mini-registry.ts lint` (dotfiles: this repo's `mini-services.yaml` against every other registry, so a second row for an existing label fails before the merge; skipped when the dotfiles checkout is absent, as on CI), then `make static` (`oxfmt --check`, `oxlint --type-aware`, `tsc --noEmit`), `make test` and `make usage` (`usage-pg` and `outbox-pg`, which apply the usage-tracker checkout's migrations: run where `make check` runs, never on the step host, no slot); `static` and `test` are each one factory test slot (`factory slot run --name "agent-workflows <step>"`; `project.yaml` `steps` declares both `remote: true`, so the factory may run them on its Linux step host when the mini's line is long). `make test` runs through `scripts/test-env.sh`, which picks the Postgres: `AGW_TEST_PG_URL` as set (CI), else a private throwaway cluster from `PG_BIN_DIR` (the step image, `tools/step-image/Dockerfile`: Ubuntu 24.04 with zsh, ffmpeg and PostgreSQL 16 server binaries, no network for the run; on the mini the default, Homebrew's `postgresql@18`), trust auth on a free loopback port, removed when the command ends (a cluster a SIGKILLed run left is removed by the next one). Never the mini's maintained Postgres: the suite peaks near 38 connections and the test role's 64 (48 before) were shared with the live processes, so a busy host failed one random test with `too many connections for role`. The step host does not see the caller's make variables: `TEST_WORKERS` and `HEAVY_WORKERS` are forwarded in the command, nothing else. `bun test --parallel=3` (`TEST_WORKERS=n`; CI sets 4 itself; each file isolated, started slowest-first from the committed `.bun-test-timings.json`), then the files in `.heavy-tests` (over 300 MiB resident alone) in a second pass with `HEAVY_WORKERS=1`: a parallel worker keeps the high-water mark of the largest file it ran (peak 4.7 GiB before, 1.9 GiB now); non-zero on any failure. A red run is cut short, since it proves nothing that ships: a failed first pass skips the heavy pass, and `TEST_BAIL=10` failures stop a pass from starting new files (bun bails at file granularity, so files already running finish); a green run runs everything. **The merge train's gate**, and what CI runs |
| `make check-fast` | The lead tier (`project.yaml` `checks: { fast: make check-fast, full: make check, ci: true }`): the same install and registry lint, `make static`, `make test-fast` and `make usage`. `make test-fast` is one test slot on the mini (named `test-fast`, not a step of `project.yaml`: the selection reads this checkout's git history) and runs what `packages/testing/src/fast-tier.ts` picks: `none` when only `docs/**` and top-level markdown changed, `bun test --changed=<merge base with origin/master>` when every changed path is TypeScript under a package other than `testing` (the tests whose import graph reaches it, in the same two passes as `make test`), and the whole suite for anything else (a script, template, JSON or markdown a package reads, the test support, a lockfile, a Makefile, an untracked path, no merge base). A test that reaches the changed code only through a spawned process or a file read is not selected: CI's `make check` on the pull request head is the gate, and the merge waits for it. |
| `make test-timings` | `make check` with `--update-timings`, pinned to the mini (`FACTORY_SLOT_REMOTE=0`: the file is written there): re-records how long each test file takes into `.bun-test-timings.json`. Run it on an idle machine and commit the result; a stale or missing entry only costs speed. Tests that run `scripts/*.sh` use `@agent-workflows/testing/zsh`: they skip where zsh is missing and fail on CI (`CI` set) |
| `make fmt` | `oxfmt --write` |
| `make deploy` | On the mini: fetch `origin/master` into `~/.agent-workflows/repo`, export it to `releases/<sha>` and `bun install --frozen-lockfile` there, render and bootstrap the LaunchAgents for that release (`com.jkrumm.agent-workflows-host` on 7791, `com.jkrumm.agent-workflows-audio` on 7792), and the gateway's (`com.jkrumm.agent-workflows-gateway` on 7794; bundled to `gateway/<build>/` and restarted only when its build changed, otherwise left running), create or extend `data/door-tokens` and check it with the host's parser before anything is stopped (the callers: Gotchas). A diff against `data/running-sha` (what the processes were started for) that touches no runtime path (`is_inert_path` in `scripts/deploy.sh`: docs, tests, CI config, READMEs; `agents/**` is runtime) restarts nothing and builds nothing: it writes `deployed-sha` only, and `make verify` compares `/health` with `running-sha`. A restart prints each process's gap (the time its `/health` did not answer; also `data/deploy-gaps.log`), and callers wait it out: the CLI up to 90 s while the deploy's marker is fresh (`AGW_RESTART_WAIT_S`), the model transports 60 s on a refused connection. A restarted gateway is stopped after host and audio and started first, and must be healthy (`build`) before they start, forward and in a rollback or redeploy recovery alike; then wait for host's and audio's `/health` (version = the sha), then `current`, `~/.config/agw/env` (with `AGW_PROCESSES`), `~/.local/bin/agw`, `data/deployed-sha`. A release where one never turns healthy is rolled back to the previous one, the restarted processes together (the gateway to its previous build directory; a gateway the deploy left running is not touched); a process left down on a failed sha (no previous release, or one that predates it) has the plist this deploy rendered removed, a failed redeploy of the live sha keeps its plists and starts the processes from them once more, naming which are up (exit 1). `DRY_RUN=1` prints the plan, every plist and the gateway's build id and decision, and changes nothing. Details: `packages/host/README.md` §Deploy |
| `make verify` | Exit 0 only if the pinned OpenCode build of the deployed release is installed (`scripts/pins.sh check`; a miss names `make install-opencode`), `/health` is ok, the deployed sha is `origin/master`, `AGW_PURPOSE=verify agw smoke ping` returns a `title`, and its `agw.runs` row is `done` with a trace id and priced usage, and a direct `AGW_PURPOSE=verify agw llm title …` left a `cap.llm.title` run `done` with priced usage, and the audio process is ok at the same sha, `agw audio ping` left a `done` run, and its door answers 401 without a caller token and the legacy 400 to an authenticated bad body, and the gateway is ok at `data/gateway-build` and three real Haiku calls through it behave (a credit pool; the same call again reading the cache; a Claude-Code-shaped one on `iu-api`) and land `usage.records` (`api_credit` with a priced cost, `api_credit`, `api_key`/`personal`) and `usage.gateway_picks` rows, a fourth with the `agw-opencode` door token lands `lane='agw_workflow'`, and the smoke run and the `cap.llm.title` run each have `source='gateway'` rows, every one qualifying (`agw_workflow`, workflow and step set, priced; `api_credit` on a pool `/health` lists or `api_key`/`personal`), and, once the host outbox synced their usage steps (`argo_synced_at`), no `source='agent-workflows'` row, all within 120 s (never waits on the Anthropic cost API). Prints the run ids and the four request ids |
| `make version` | Print the deployed commit sha (`~/.agent-workflows/data/deployed-sha`, `AGW_ROOT` redirects), one line, read-only; the factory checks a shipped commit against it. `project.yaml` (deploy mode `make`, target `mini`, `verify: make verify`, ship by pull request, `checks` fast tier)  is the factory manifest |
| `make hyperdx-apply` | Upsert the prod HyperDX dashboard `agw` and its seven alerts (tag `agw`, webhook `Factory door`) from `packages/hyperdx/definitions` by name, through the `agw hdx` door (no credential here); `ARGS=--dry-run` validates and prints the plan, `make hyperdx-export` writes the live ones back (capture a UI edit). Thresholds, their 14-day backtest and what the dashboard cannot show: `packages/hyperdx/README.md`. Run it after editing a definition; a change to the definitions is not live until then |
| `make eval-mine-iris` | Write the cases of the `iris-triage` and `iris-gist` eval suites (`packages/host/src/workflows/iris-triage/README.md`) from the journal's recorded Iris calls (runs of purpose `iris`, read-only) into `$AGW_EVAL_DIR` (mode 0600, never committed). Reads the journal password through `.env.journal.tpl` (`secrets-run`) and connects to the journal on `127.0.0.1:5432`, so it runs on the mini. Prints the case counts, never a text |
| `make live-routes` | One real call per route: every route on the `anthropic` or `opencode` wire and every `iu-openai` text route (`agw routes`; `ROUTES='a b'` narrows), each as `AGW_PURPOSE=verify agw smoke route <id>` (a fixed prompt; media routes are refused), four at a time, then within 120 s a `source='gateway'` `usage.records` row of the run with the route's model, `cost_usd` and lane `agw_workflow`, and the run's `agw.runs` row `done` with a cost. Prints route, model, billing, account, input, cache read, output, cost, run id; exits non-zero naming each failed route. Costs cents. A Claude alias in a route resolves through `CLAUDE_ALIASES`, read from the source of the deployed release (`~/.agent-workflows/current/packages/routes/src/table/claude.ts`, via `bun`); a missing or malformed map fails the run, there is no copy in the script. The proof behind a changed route; needs the `smoke` agent for opencode routes |
| `make research-chrome` | Install and start the headed Chrome LaunchAgent (`com.jkrumm.research-chrome`, DevTools on loopback `127.0.0.1:9222`, profile `~/.local/share/research-chrome`) that `web.fetch` falls back to for pages a plain client cannot read and for empty-shell reads (no list items, JavaScript-required or no-results notice), before other URL spellings and Tavily Extract (`packages/capabilities/README.md` §`web.fetch` chain) (`AGW_BROWSER_CDP_URL` in `.env.tpl`). Not part of a release; idempotent, an unchanged loaded agent is left alone. A Chrome that cannot pass a challenge returns `blocked` `needs-human`: the read reports the host and reason and the caller goes on with other sources; nobody is asked unless the call set `humanAssist` (`--human-assist`; `packages/capabilities/README.md` §Bot checks are reported, and handed to the owner only when the call asks) |
| `make install-opencode` | Install the pinned OpenCode build (`OPENCODE_VERSION`, `packages/opencode-host/src/server.ts`) under `~/.local/share/agent-workflows/opencode-bin/<version>` with a `current` link; link `~/.local/bin/opencode` and `opencode-safe` to this checkout's `scripts/` (refused from a linked worktree, so run it in the main checkout). Idempotent (a present version is not downloaded again); never restarts the host, whose OpenCode server runs the new binary on its next start. Upgrade steps: `packages/opencode-host/README.md` §Pinned build |

CI (`.github/workflows/ci.yml`) runs `bun install --frozen-lockfile` and `make check` on pushes to `master` and
on pull requests, on GitHub-hosted runners. Changes land by pull request (`project.yaml` `ship: via: pr`): the full gate runs there on the exact head, and leads run `make check-fast` locally.

`make check` needs Postgres: tests read `AGW_TEST_PG_URL` and fail when it is unset; `scripts/test-env.sh` starts a private cluster and sets it, unless it is already set (CI uses a `postgres:18` service). `packages/middleware/test/usage-pg.test.ts` also needs `USAGE_TEST_PG_URL` (an admin connection, set by the same script) and the usage-tracker checkout beside this repo (`USAGE_MIGRATIONS_DIR` overrides, needed from a linked worktree); without either it skips with the reason in its name, so it never runs in CI. Each test file works in its own throwaway schema. Each test file sets a load-scaled default timeout as it starts (a few files that run real scripts set a fixed one with `setDefaultTimeout`) (`packages/testing` preload from `bunfig.toml`: 5000 ms × 1-minute load average per core, floor 5000, cap 30000; Bun binds a timeout at test registration, so per file is the finest grain); a test with its own explicit timeout keeps it.
